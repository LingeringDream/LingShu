# 加密云同步

桌面端「云账户 → 加密云同步」提供手动同步。首次使用生成并备份恢复密钥，勾选已备份后开启；其他设备登录同一云账户、输入同一密钥，再点击「立即同步」。登录本身不上传记忆。

## 当前范围

- 仅个人私有、未关联项目的记忆，包含正文、类型、重要性、治理状态、时间、标签、元数据和软删除状态。
- 保留记忆 UUID，接收记录后供本地记忆检索及本地 MCP 使用；向量由接收设备的模型重新生成，失败不回滚已落库记忆。
- 不同步聊天、项目、团队记忆、ACL、模型配置、登录凭据、访问计数或向量；跨设备 MCP 远程访问仍未开放。
- `superseded_by` 外键、项目关系及治理事件不跨设备复制。治理状态会同步，但完整治理关系图不在本期范围内。已有本地关系不被导入重置。
- 每账户最多 10,000 条记录（包括墓碑），每条明文最多 35,000 UTF-8 字节；不自动清理删除墓碑，避免离线设备复活已删除记录。
- 本期为用户触发的同步，未实现后台定时同步、密钥轮换、附件同步、账户数据清空或完整备份恢复。

## 密钥与加密

使用 Web Crypto 生成 256 位随机恢复密钥，AES-256-GCM 加密，随机 96 位 IV、128 位认证标签。AAD 绑定协议版本、云账户、记忆 UUID、修订号与密钥指纹，防止密文被挪到其他账户、记录或版本。密钥不是登录密码，无口令派生或服务器找回功能。

云端只保存密钥 SHA-256 指纹、记录 ID、修订号、更新时间及密文。正文和删除状态均在密文中；数量、大小和更新时间仍是可见元数据。桌面密钥按云账户分别保存于系统 keyring，命令限主窗口调用；浏览器模式不持久保存密钥。退出账户移除页面中的密钥引用，但保留系统保险库里的账户专属密钥；「移除本机同步密钥」删除该密钥，不删除本地数据或云端密文。

算法参数参考 [Web Crypto AES-GCM](https://developer.mozilla.org/en-US/docs/Web/API/AesGcmParams)。本功能不能防御已被控制的客户端或回滚到客户端从未见过的合法旧状态；已见到更高版本的客户端会拒绝显式版本回退。

## 同步与冲突

每次分页比较本地记录和云端版本清单，仅传输变更的密文。同步基线只存修订号和规范化 JSON 的 SHA-256，按云账户、本地用户及密钥指纹隔离，不保存明文或密钥。基线丢失时不会猜测哪台设备更新；不同内容进入冲突处理。

云端以 `base_revision` 条件写入，不使用设备时间判断胜负。本地导入对记录内容指纹加行锁校验，检测同步期间的新编辑；首次导入也受 UUID 唯一约束保护。失败后可重新同步；写入成功但响应丢失时，下次通过内容一致性重新建立基线。

同一记录两侧均修改（包括编辑与删除）时保持双方数据，界面显示两侧内容，用户选择本机或云端版本。选择云端会覆盖界面显示的未同步本机版本；这份本机旧版本不会凭空出现在云端历史。选择本机会通过云端 CAS 保存，旧云端版本进入密文历史。云端每条保留最近 10 个已同步的旧版本，冲突界面可解密查看；暂不提供一键历史恢复。

## 服务与发布

### 分支合并兼容性

合并远端 `211b5e2` 时保留其整库快照协议：`GET/PUT /api/v1/sync`、`GET /api/v1/sync/history` 由 `snapshotSync.ts` 处理，使用 `0006_pro_sync.sql` 的独立表和 R2 对象。当前默认界面仍使用本文的逐条协议 `/api/v1/sync/vault`、`/api/v1/sync/records/*`，整库同步组件不挂载，防止两套自动合并策略同时生效。两套密钥格式和数据格式不同，不能互换。

两个迁移文件虽然都以 `0006` 开头，但完整文件名及数据库对象不同；保留原文件名以兼容已经记录迁移名的环境，不重命名或重跑已应用的迁移。下次发布合并后的 Worker 前必须应用尚未执行的快照迁移。生产部署记录下方的版本仅包含逐条协议，不代表本次 Git 合并已重新部署。

兼容快照写入使用每次请求唯一的 R2 对象路径，避免同版本并发写入的失败方删除成功方密文；客户端快照操作也绑定发起同步时的云账户。远端检索参数本地持久化和按需加载保留，开发版记忆实验台继续使用统一的版本开关。

云端所有 `/api/v1/sync/*` 请求重新验证会话、设备撤销状态和有效 Pro / Team 权益；与账户展示保持一致，现有团队成员也具有 Team 使用权益。取消或到期不删除密文，但停止同步读写。跨设备 MCP 使用独立的未开放功能码，不能因开启同步而误开。

本地 `/api/v1/cloud-sync/memories` 仅接受本地会话，不接受云会话；它是本地导入导出能力，不设置付费墙。云账户凭据只发送到固定的账户域名。

上线顺序：

1. 在 `lingshu-cloud` 执行 `npx wrangler d1 migrations apply lingshu-cloud-dev --remote`，应用 `0006_encrypted_sync.sql`。
2. 执行 `npm run build`、`npm test`、`npm run check` 后部署 Worker。
3. 构建并分发包含新增 Rust 路由、keyring 命令和同步界面的桌面端；旧桌面客户端没有同步入口。
4. 使用专门的 Pro 测试账户进行真实双设备验收。不要用用户个人记忆作为部署冒烟数据。
