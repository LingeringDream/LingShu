## 二、写法要点（五条）

1. **未来规划 = 已完成 / 未完成的差额。** 上一节是"已完成"，本节规划只覆盖剩下的缺口，两者拼起来正好是完整图景。
2. **每条带验收口径。** "提升检索效果"是空话；"在同 Top-K 同预算条件下证明上下文 Token 下降，并给出下降幅度"才是规划。
3. **三阶段足够**：补证据（2026 年 9 月—12 月）→ 做产品（2027 年上半年）→ 建平台（2027 年下半年—2028 年）。
4. **技术线 / 产品线 / 商业化线分开写**，混在一起最容易变成空话。
5. **长期部分克制**：只写方向和前提条件，不写收入或用户数承诺。

## 三、可直接粘贴的正文

### 3.1 总体思路

> 灵枢的未来规划遵循一条主线：**先让已有结果变成可验收的证据，再让系统变成可交付的产品，最后让记忆层变成可复用的基础设施**。
>
> 当前版本已在自建长时序回归集上取得 94% 的 Top-1 准确率（静态 RAG 基线 62%），10 万条规模下检索 P99 为 195.19 毫秒，内存占用下降 61.78%，macOS 与 Windows 独立安装包均已内嵌数据库，MCP 二进制与部分客户端一键配置也已交付。但仍存在三类明确差距：其一，部分结果仍属于离线与功能性验证，尚未形成可验收的统计证据；其二，事实状态的自动识别尚未达标；其三，Linux 一体化交付、三平台发布验证与部分手动配置客户端的接入体验仍需完善。规划围绕这三类差距展开，按"补证据—做产品—建平台"三步推进。

### 3.2 分阶段路线

| 阶段 | 时间 | 主题 | 关键交付 |
|---|---|---|---|
| 第一阶段 | 2026 年 9 月—12 月 | 补证据：把阶段性结果变成可验收结论 | 在线检索接入、同预算 Token 对照、多相关证据评测集、百万级与真实并发、自动治理达标路径 |
| 第二阶段 | 2027 年上半年 | 做产品：从可运行系统到可交付产品 | Linux 一体化安装包、三平台发布验证与升级、剩余 MCP 客户端接入优化、Pro 云能力与 Team 增量能力开放 |
| 第三阶段 | 2027 年下半年—2028 年 | 建平台：从单一产品到记忆层基础设施 | 企业级 Gateway、SDK 与 OEM、端侧小模型、记忆可移植协议 |

### 3.3 第一阶段：补证据（2026 年 9 月—12 月）

**（1）把离线结论接入在线链路**

LoCoMo 上新增的 BM25 检索策略目前仍是离线实验结果，尚未接入在线生产检索链路。规划将其接入在线服务，在同一数据与同一接口下复现离线结论，并给出真实服务的 QPS、并发 P99 与错误率。

**（2）补齐尚未成立的指标口径**

- **Top-K 精准率**：当前标准 P@5 为 19.80%，且自建集每题仅一个相关证据，理论上限为 20%。规划新建"每题含多个相关证据"的评测子集，或取得命题方对 Top-K 指标定义的书面确认，再行验收 83% 的阈值。
- **Token 消耗**：历史 57.83% 的下降来自不同 Top-K 的对照。规划在同 Top-K、同预算条件下重新对照，证明上下文开销的真实下降幅度。
- **复杂任务完成度**：当前为 3 个开放域任务的对照结果，样本过小。规划扩充到可统计规模，并按任务类型分别报告。

**（3）打通自动治理的达标路径**

自动状态识别尚未达标：事实状态自动判定的 Macro-F1 为规则 44.74%、LLM 22.97%，错误淘汰率 23–27%，远高于 <5% 目标；18 例治理案例中的 0% 错误淘汰属小样本，不外推。当前线上行为是保守的争议保留加人工裁决。规划按"先修测量、再修标签、最后修算法"推进：

1. 完成 73 组盲审包的双人独立复核与分歧裁决，明确 active / superseded / stale / duplicate / unresolved 各自的判定证据要求；
2. 冻结新一版的规模、类分布、指标与阈值后再观察结果，避免按测试分数反复调参；
3. 验收口径从"分类准确率"改为"同一排序条件下的下游检索 Oracle gap"——只替换状态预测来源（none / oracle / rule / LLM），比较任务得分差。

**（4）规模与真实场景**

- 开展百万级记忆索引、真实服务并发 QPS、P99 与资源占用的工程压测（当前仅有 10 万条规模的离线探针）。
- 引入真实用户样本与真实多 Agent 协作任务，替代纯合成数据与单元级权限测试。
- 条件允许时接入除 LoCoMo 之外的公开长记忆评测集，形成"公开集 + 自建集"的双轨结论。

### 3.4 第二阶段：做产品（2027 年上半年）

| 方向 | 当前状态 | 规划目标 |
|---|---|---|
| 一体化安装包 | macOS 与 Windows 已内置嵌入式 PostgreSQL；Linux 仍无一体化交付 | 补齐 Linux 安装包，并继续优化三平台首启耗时与安装体积 |
| 原生能力 | macOS 用 EventKit，其余平台降级为 ICS 导出 | Windows 增加 UI Automation 屏幕读取；日历接入 Microsoft Graph 或 CalDAV |
| 工程化 | 已有 macOS 与 Windows 构建任务 | 补齐 Linux 构建、安装包签名、自动升级与崩溃恢复，形成三平台构建矩阵 |
| MCP 接入 | 安装包已携带二进制，设置页可为支持的客户端一键写入配置；部分客户端仍需手动粘贴 | 补齐手动配置客户端的引导与可验证检测 |
| 版本能力 | Team 工作区创建与受邀加入已开放；加密云同步、跨设备 MCP、高级治理、团队 MCP 与按席位账单未开放 | 开放 Pro 云能力与 Team 增量能力，不重复规划已有团队工作区 |
| 检索策略 | 六维权重为固定值，消融显示并非各分布最优 | 按任务与信号可用性做权重路由，在开发集学习、独立测试集验收，保留固定权重版本作为对照 |

验收原则：三个平台核心能力表现一致，macOS 专属能力在其他平台合理降级，不出现误导性入口。

### 3.5 第三阶段：建平台（2027 年下半年—2028 年）

1. **企业级 Memory Gateway**：Agent 身份、RBAC、SSO、审计与来源追踪，支持云、VPC 与私有部署。
2. **API / SDK 与 OEM**：提供 Python / TypeScript SDK 与白标方案，让第三方 AI 产品直接获得记忆与冲突治理能力。
3. **端侧模型**：用本地小模型承担事实抽取与离线合并，降低 Token 消耗与端到端时延，支撑完全离线场景。
4. **记忆的可移植与用户主权**：开放记忆导入、导出与跨产品迁移，推动记忆层的开放协议与审计标准。
5. **垂直场景落地**：优先选择研发协作、智能客服、教育陪练三类高频使用 AI 的场景做深度验证。

### 3.6 商业化路径

商业化围绕"记忆的覆盖范围"逐级展开，而不是限制用户在本机通过 MCP 使用自己的记忆：

- **Free**（已开放）：单机本地记忆与本地 MCP，承担体验与获客；
- **Pro**：加密云同步与多设备连续记忆、跨设备 MCP，按订阅收费；
- **Team**：当前已提供工作区创建、受邀加入、成员角色与记忆授权；团队 MCP 与统一账单属于后续付费增量；
- **Enterprise / Embedded**：企业统一上下文中心与第三方产品嵌入，属独立产品形态，按项目或授权收费。

近期不做收入预测，先验证三个指标：MCP 接入的周活跃用户数、Free 到 Pro 的转化率、跨设备同步的次月留存。

### 七、未来规划

#### 7.1 总体思路

灵枢未来三年的发展遵循"先验证、再交付、后平台化"的路径推进。

当前阶段，项目已完成三层记忆沉淀、多智能体权限空间、时序冲突治理与自适应检索的全链路原型，并在量化验证上取得阶段性结果：在包含 660 轮记忆和 300 条查询的自建长时序回归集上，独立测试集 Top-1 准确率达到 94%，静态 RAG 基线为 62%；在 10 万条记忆规模下，离线检索 P99 时延为 195.19 毫秒，过滤后内存占用下降 61.78%；macOS 与 Windows 独立安装包均已内置嵌入式数据库，无需依赖外部服务即可启动。

对照命题要求，项目仍存在三类差距：一是部分结果属于离线实验与功能性验证，尚未形成可验收的统计证据；二是事实状态的自动识别尚未达标，当前线上行为仍为保守的争议保留加人工裁决；三是 Linux 一体化交付、三平台发布验证与部分客户端的 MCP 接入体验仍需完善。未来规划围绕这三类差距展开，分近期、中期、远期三步推进。

#### 7.2 阶段目标

| 阶段 | 时间 | 重点任务 | 标志性成果 |
|---|---|---|---|
| 近期 | 2026 年 9 月—12 月 | 将公开数据集的检索策略接入在线生产链路；在同 Top-K 同预算条件下重测上下文开销；构建每题含多个相关证据的评测子集以验收 Top-K 精准率；开展百万级规模与真实服务并发压测；引入真实用户样本与真实多智能体协作任务；按"标签盲审—冻结评测集—改用下游任务增益验收"的路径推进自动治理 | 形成"公开数据集 + 自建数据集"双轨评测体系，自动治理错误淘汰率降至 5% 以下 |
| 中期 | 2027 年 1 月—6 月 | 完成 Linux 一体化安装包；补齐 Windows 屏幕读取与跨平台日历同步；建立三平台自动构建、签名、验证与升级机制；补齐需手动配置的 MCP 客户端引导；开放专业版云同步、跨设备接入与团队版增量能力 | 三个平台核心体验一致，规划付费能力正式上线 |
| 远期 | 2027 年 7 月—2028 年 12 月 | 建设企业级记忆网关，支持智能体身份、分级授权、单点登录与私有部署；提供软件开发工具包与白标方案；引入端侧小模型承担事实抽取与离线合并；推动记忆的导入导出与跨产品迁移 | 第三方 AI 产品可通过标准接口接入灵枢记忆层 |

#### 7.3 商业化与社会价值

商业化围绕"记忆的覆盖范围"逐级展开：免费版提供单机本地记忆与本地 MCP 接入，承担体验与获客；专业版计划以加密云同步和多设备连续记忆为核心，按订阅收费；团队版已提供工作区创建、受邀加入、成员角色与记忆授权，后续以团队 MCP 和统一账单作为付费增量；企业版与嵌入版面向组织与第三方产品，按项目或授权收费。近期以 MCP 接入活跃度、免费到付费的转化率、跨设备功能的次月留存三项指标验证商业模式，暂不做收入预测。

在用户数据层面，项目坚持本地优先原则，记忆的写入、读取与授权均由用户控制，支持导出与彻底删除。后续引入真实用户数据时，将同步建立授权、审计与合规机制，确保记忆能力的可控与可追溯。

## 六、避坑清单

- 不要把已完成项写成规划：端侧时延、内存下降、Windows 内嵌数据库、长时序 94% 都已达标，再写就是自曝没读材料。
- 不要写"P@5 达到 83%"，单相关证据题的上限是 20%，这条已被明确撤回过一次。
- 不要把 Token 下降 57.83% 写成达标结论，它来自不同 Top-K 的历史对照。
- 不要只写技术规划不写商业规划，创新大赛评分通常包含商业维度。
- "引入真实用户数据"必须与隐私合规方案同步写（本地优先、明确授权、可删除、可导出），否则一问就崩。
- 不要写"打造 AI 生态""成为行业领先"这类无法验证的表述，替换成可验收的动作。
