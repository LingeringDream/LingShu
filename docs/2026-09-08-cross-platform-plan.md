# 灵枢跨平台实施计划书

版本：跨平台验证版

提交日期：2026年9月8日

实施周期：2026年8月31日至2026年9月8日

文档性质：历史阶段计划；当前产品范围以 [产品范围](product-scope.md) 为准。

## 一、项目目标

本阶段以2026年9月8日阶段验证为节点，在保留灵枢现有核心能力的基础上，完成跨平台能力梳理、重点功能调整、测试验证和演示版本打包。

跨平台版本采用“macOS完整桌面版 + Windows/macOS通用Web版 + Windows桌面验证版”的交付策略。核心记忆、人格演化、主动服务和项目管理能力共用一套代码；日历、屏幕读取、应用调用等操作系统能力通过平台适配或功能降级处理。

本阶段不以实现所有平台的原生功能完全一致为目标，而以“核心功能可跨平台运行、macOS原生能力完整展示、Windows版本可以安装验证、演示现场稳定演示”为验收原则。

## 二、当前项目基础

| 模块 | 当前技术 | 当前状态 | 跨平台判断 |
|---|---|---|---|
| 前端 | React 18、TypeScript、Vite | 浏览器和Tauri共用 | 具备跨平台基础 |
| 后端 | Rust、Axum、Tokio | 核心服务无明显系统绑定 | 具备跨平台基础 |
| 桌面外壳 | Tauri 2 | 已完成macOS主窗口和桌宠窗口 | 可扩展到Windows和Linux |
| 数据库 | PostgreSQL | 后端启动时必须连接 | 安装即用的主要阻碍 |
| 缓存 | Redis | 连接失败时可以降级 | 不阻塞基础版本 |
| 向量检索 | Qdrant | 连接失败时可回退SQL检索 | 不阻塞基础版本 |
| 大模型 | Ollama或OpenAI兼容接口 | 支持本地和云端模型 | 可跨平台 |
| 系统日历 | macOS EventKit | 仅macOS可用 | Windows需降级或新增适配 |
| 屏幕读取 | macOS Accessibility | 仅macOS可用 | Windows需UI Automation适配 |
| 应用和文件打开 | macOS open、mdfind | 仅macOS完整可用 | Windows需系统接口适配 |
| PDF读取 | pdftotext、textutil、Python、mdls | 依赖本机工具 | 需改为跨平台实现 |
| 自动发布 | GitHub Actions | 只有macOS构建任务 | 需增加Windows构建任务 |

## 三、跨平台总体方案

跨平台改造不重写现有系统，继续使用React、Rust和Tauri技术栈，将产品划分为通用核心层、平台能力层和交付运行层。

通用核心层：

- 对话与模型管理。
- 三层记忆和灵魂账本。
- 人格演化。
- 思绪队列和主动建议。
- 项目管理。
- 日历事件草稿。
- 权限、审计和用户设置。

平台能力层：

- macOS继续使用EventKit和Accessibility API。
- Windows优先实现通用文件能力、桌宠和ICS日历导出。
- Web版本隐藏无法在浏览器内完成的系统级操作。
- 前端不再只判断是否运行于Tauri，而是根据具体能力决定显示、禁用或降级功能。

交付运行层：

- macOS提供完整桌面演示版。
- Windows提供安装验证版。
- Web版本作为跨平台体验入口和演示现场备用入口。
- 验证阶段优先使用统一后端服务，避免要求体验者安装PostgreSQL、Redis、Qdrant和Ollama。

## 四、市场调研计划

### 4.1 调研目的

调研跨平台个人智能助理、智能体记忆系统和桌面智能助手的产品形态，明确灵枢在跨平台产品中的差异化定位，并为跨平台功能取舍提供依据。

### 4.2 调研对象

| 类别 | 调研重点 | 预期产出 |
|---|---|---|
| 通用AI助手 | 对话、文件、搜索、跨设备体验 | 基础功能对比 |
| 桌面智能助手 | 桌宠、悬浮窗口、系统调用 | 桌面交互对比 |
| 个人知识库 | 记忆沉淀、检索、用户画像 | 记忆能力对比 |
| 智能体平台 | 工具调用、权限、安全、审计 | 工程能力对比 |
| 日程管理产品 | 日历同步、提醒、主动建议 | 日程能力对比 |

### 4.3 重点调研问题

- 竞品是否具有长期记忆，记忆是否可以解释、修改和遗忘。
- 竞品是单纯聊天工具，还是能够主动发现问题并给出建议。
- 竞品如何处理个人隐私、系统权限和操作审计。
- 竞品支持哪些平台，各平台的功能是否一致。
- 用户是否愿意为了本地部署安装Docker、数据库和本地模型。
- 灵枢的三层记忆、人格演化和主动服务如何形成可测量差异。

### 4.4 调研结果呈现

调研结果形成以下材料：

- 一份竞品功能对比表。
- 一份目标用户和核心痛点说明。
- 一页灵枢差异化定位说明。
- 三至五条可用于产品介绍的市场结论。

## 五、功能改造计划

### 5.1 P0：阶段验证前必须完成

| 功能 | 改造内容 | 验收标准 |
|---|---|---|
| 平台能力检测 | 增加平台和能力查询接口 | 前端可以区分macOS、Windows和Web能力 |
| 前端能力降级 | 按能力显示、禁用或替换入口 | Windows不再误调用EventKit等macOS接口 |
| 日历跨平台 | macOS保留EventKit；Windows和Web增加ICS导出 | 三个平台均能完成日历事件的有效交付 |
| 文件打开 | 使用Tauri通用文件打开能力 | macOS和Windows能调用默认应用打开文件 |
| 用户目录 | 使用跨平台目录接口替代单独读取HOME | Windows能正确识别用户目录 |
| 后端地址 | HTTP和WebSocket统一使用可配置地址 | 不在多个文件中分别写死8080地址 |
| Sidecar生命周期 | 启动、退出、端口占用给出明确处理 | 退出客户端后不遗留异常后端进程 |
| Windows构建 | 构建Windows后端Sidecar和Tauri安装包 | 在Windows真机完成安装和启动 |

### 5.2 P1：跨平台版本尽量完成

| 功能 | 改造内容 | 处理原则 |
|---|---|---|
| PDF读取 | 使用纯Rust PDF解析库 | 减少系统工具和Python依赖 |
| 桌宠窗口 | 验证透明、置顶、拖动和任务栏隐藏 | Windows不支持的效果允许降级 |
| 云端模型 | 配置OpenAI兼容模型服务 | 演示现场不依赖本地Ollama |
| 远程后端 | 配置可控的演示服务 | 降低体验者电脑的安装要求 |
| 错误提示 | 增加平台不支持和服务不可用提示 | 不向用户展示底层异常文本 |

### 5.3 P2：赛后完善

| 功能 | macOS方案 | Windows方案 | Linux方案 |
|---|---|---|---|
| 系统日历 | EventKit | Microsoft Graph或系统日历接口 | CalDAV或ICS |
| 屏幕读取 | Accessibility API | UI Automation | AT-SPI |
| 应用自动化 | open及系统脚本 | ShellExecute和UI Automation | xdg-open和桌面接口 |
| 本地数据 | PostgreSQL或后续嵌入式存储 | SQLite或嵌入式存储 | SQLite或嵌入式存储 |
| 安装包 | DMG | MSI或NSIS | AppImage或DEB |

## 十、最终交付标准

跨平台版本本完成的判断标准如下：

- 有可运行的macOS完整桌面版。
- 有经过真机验证的Windows安装版。
- 有可访问的Web体验版或本地Web备用方案。
- 核心对话、记忆、人格和主动服务功能在三个入口表现一致。
- macOS专属功能在Windows和Web中具有合理降级，不出现误导性入口。
- 有平台兼容性测试记录和完整演示脚本。
- 安装包、源代码、测试报告、说明文档和演示视频均标注同一版本号。
- 所有提交材料在2026年9月8日前完成最终校验。

## 十一、后续发展路线

阶段验证后，跨平台工作按照以下顺序继续：

1. 将PostgreSQL必选依赖改为嵌入式存储或本地、云端双模式。
2. 完成Windows UI Automation屏幕读取适配。
3. 接入Microsoft Graph、Google Calendar或CalDAV。
4. 建立macOS、Windows、Linux自动构建矩阵。
5. 完成安装包签名、升级和崩溃恢复机制。
6. 将移动端设计为轻客户端，通过安全接口访问灵枢核心服务。
